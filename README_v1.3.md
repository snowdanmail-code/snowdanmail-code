# AI Remote Control GPT v1.3 — Latency & Deadline Safety

Дата: 2026-10-17. Статус: **локальный лабораторный прототип**, не автономный игрок с реальными деньгами. Сохранены все модули и регрессионные тесты v1.2.

## Что реально изменено

- `server/arc_fastloop/`: проверяемый модуль свежести кадров, дедлайнов, latest-sequence-wins, запрета параллельной обработки одного сеанса и статистики задержек. **Не выдаёт команды для денежных действий**.
- `POST /fast/observe`: защищённый `X-Device-Token` read-only HTTP маршрут. Ответы без `action` для касания; в протоколе всегда `action: null`, `money_actions_enabled: false`.
- `server/arc_vision/card_reader.py`, `money_reader.py`, `combined_observer.py`: вместо двух декодирований JPEG одно декодирование и передача общего BGR кадра обоим модулям. Старые публичные методы чтения сохранены.
- Android: `FastCapturePolicy.kt`, время создания кадра, проверка возраста JPEG, видимый быстрый режим (~2 кадра/с) и пользовательский STOP. Отдельный pure Kotlin тест.
- Добавлен **четвёртый профиль** `1536 px / Q75`: на фактическом тестовом JPEG он позволяет надёжнее читать карты, чем прежние 720/960/1280 px. Это наблюдение на ограниченной выборке, не гарантия для всех кадров.
- В существующем Android контуре GPT добавлены проверки возраста кадра при отправке и ответе. Ответ позднее 1800 мс относительно времени кадра **отбрасывается**, даже если снимок визуально не поменялся. Для старого `/poker/decide` сервер сохраняет блокировку реальных денежных действий по умолчанию.

## Схема быстрого цикла

`MediaProjection` → локальный coarse change detector → latest-only JPEG (~2 кадров/с) → защищённый сервер → единое декодирование → распознаватели карт/сумм → контроль версии/состояния → отчёт и STOP при неопределённости.

GPT здесь намеренно **вне быстрого критического пути**: его ответы через сеть могут поступать через секунды, и недопустимо гарантировать соблюдение 30-секундного таймера без реальных измерений. Критический путь для денежных действий **не разрешён** и не тестировался на 1win.

## Временные ограничения

| Узел | Лабораторная политика |
|---|---|
| Android sampling | не чаще 1 раза в 300 мс |
| Быстрый upload | не чаще 1 раза в 500 мс, в полёте максимум 1 запрос |
| Старый кадр | > 1300 мс: отменить локальную обработку |
| Бюджет локального CPU | до 1200 мс, иначе поздний результат отбросить |
| Отсутствие запаса времени | < 3000 мс заявленного остатка: не запускать анализ |
| HTTP в быстром режиме | connect 1000 мс, read 1800 мс |
| Старый GPT контур | 1800 мс после формирования кадра: поздняя команда отбрасывается |

Важно: `remaining_ms=10000` в тестовом Android быстром режиме — **искусственный лабораторный бюджет**, а НЕ реально распознанный таймер 1win. Его нельзя использовать для обоснования действия на реальные средства. Реальное чтение таймера и подпись момента начала хода — задачи следующих этапов.

## Результаты на этом сервере (НЕ смартфон!)

По `BENCHMARK_v1.3.json`: 3 ранее известных изображения × 10 повторов, CPU.

- Composite, **предыдущая** схема двойного JPEG decode: медиана 3.44 мс; p95 7.69 мс.
- Composite, **новая** схема decode once: медиана 2.21 мс; p95 3.82 мс.
- На этом узком CPU-фрагменте медиана меньше примерно на 36%. Это не включает захват Android, сеть, GPT, движение интерфейса или реакцию сервиса Accessibility.
- `PROFILE_RESOLUTION_v1.3.json`: на ограниченном кадре 720/960 px не поддерживаются шаблонами измерителя; на 1280 px полное чтение карт не подтвердилось; на 1536 px Q96 все карты и банк прочитаны, также отдельно проверен профиль 1536 px Q75. Не распространять эти результаты на другие разрешения и шрифты без тестов.

## HTTP-контракт read-only лабораторного режима

`POST /fast/observe`, заголовок `X-Device-Token`:
```json
{
  "request":"fast_observe",
  "session_id":"unique-session-id-0001",
  "sequence":1,
  "frame_age_ms":120,
  "remaining_ms":10000,
  "screen_state":"unknown",
  "image_base64":"<base64 JPEG>"
}
```
В ответе `fresh_observation`, `stale_frame`, `timer_insufficient`, `busy_dropped_old`, `discarded_superseded`, `discarded_deadline` и т.п. Если устарело или пришёл более новый кадр, `observation` вообще не возвращается.

## Что ещё не готово

- APK не собран (в контейнере **нет Android SDK/Gradle**), нет теста на смартфоне.
- Нет доступа к учётной записи 1win, нет удалённого управления телефоном и живых действий за столом.
- GPT API не испытан: нет подключённого платёжного API-ключа или замера сетевой задержки.
- Не реализованы достоверное чтение таймера и очереди хода, всей структуры ставок и диапазонов соперников. Скорость полного принятия решений не подтверждена.
- Нет оснований считать положительный выигрыш/EV в реальной игре подтверждённым; тесты серверной логики этого не доказывают.
- Подмена профилей, вход за стол и денежные действия требуют отдельной проверки и не включаются в быстрый маршрут.

## Следующие критерии допуска

1. Компиляция APK и проверка разрешений MediaProjection/Accessibility на устройстве.
2. Замеры end-to-end p50/p95/p99 для захвата→доставки→распознавания→ответа при Wi-Fi и LTE.
3. Калибровка распознавания карт, ставок, смены хода, 30-секундного таймера на **независимых раздачах**, а не повторных кадрах того же борда.
4. Тесты отключений, поддельных/старых кадров, повторных ответов, смены стола и аварийного STOP.
5. Проверка математической модели в симуляторе и отдельные пост-сессионные разборы, только после полного выхода из столов.
