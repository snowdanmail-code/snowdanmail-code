## Один новый инженерный модуль

`tools/apk_release_gate.py`: проверяет полученный Android Gradle debug APK,
его ZIP-структуру, package name, versionCode/versionName, minSdk/targetSdk,
флаг debuggable, успешную проверку современной схемы подписи через официальный
`apksigner`, SHA-256. При любой ошибке останавливает процесс, не выдаёт
артефакт за проверенный. Записывает `APK_ATTESTATION_v2.9.json` и `.apk.sha256`
только после реальной проверки. Это не проверка выполнения на телефоне.

Сборка в `.github/workflows/ci.yml` и `tools/build_android_debug.sh`
теперь обязана пройти этот gate перед публикацией APK. Windows-скрипт
`windows/01_BUILD_APK.ps1` также запускает проверку перед сообщением об успехе.
Параметры: Gradle 8.9, AGP 8.7.3, Android SDK Platform 35, build-tools 35.0.0,
JDK 17, debug-only конфигурация с выключенными внешними действиями.

## Как получить APK в разрешённой среде

1. Установить Android SDK 35 и build-tools 35.0.0, JDK 17 и Gradle 8.9.
2. Запустить `bash tools/build_android_debug.sh` в Linux/CI или
   `windows/01_BUILD_APK.ps1` в Windows. Скрипт автоматически проверяет
   подпись, идентификатор и версию перед выдачей артефакта.
3. Либо поместить проект в доступный приватный репозиторий GitHub:
   `.github/workflows/ci.yml` соберёт и проверит debug APK и опубликует
   его вместе с SHA-256 и JSON-аттестацией **только если сборка пройдёт**.
4. На устройстве отдельно проверить установку, MediaProjection, уведомление
   STOP и распознавание без отправки игровых действий во внешнее приложение.
