# Версии и откат — практическая инструкция

**Статус: работающий локальный лабораторный прототип.** Это не production-контроллер и не доказательство профессиональной игры AI.

## Модули

`server/arc_versions/registry.py` — хранение, сверка SHA-256, зависимости, релизы, контрольные точки и атомарная смена ссылки.  
`server/arc_versions/contracts.py` — контракты сменяемых поставщиков.  
`server/arc_versions/sandbox.py` — безопасный учебный математический сервис и политика `wait`.  
`server/arc_versions/cli.py` — локальные команды, без интернета.  
`server/arc_versions/seed_lab.py` — демонстрация восстановления на копиях исходников v0.6/v0.7.

## Безопасный тест без телефона

Откройте папку `server` в терминале Linux/Termux:

```sh
python -m unittest discover -s tests -p 'test_*.py' -q
python -m arc_versions.cli --dir ./demo-registry status
python -m arc_versions.cli --dir ./demo-registry --demo-offline activate cp-demo-sandbox
python -m arc_versions.cli --dir ./demo-registry --demo-offline activate cp-demo-baseline
```

Флаг `--demo-offline` разрешает переключение **только в учебном сценарии**. Он не проверяет реальный клиент 1win; не используйте этот пример как подтверждение закрытия стола.

Параметр `ARC_VERSION_REGISTRY_DIR` можно установить на путь реестра, чтобы по защищённому запросу `GET /versions` получить статус (только чтение). Стартовый API ограничен `127.0.0.1`; без дополнительной TLS и авторизации не открывать наружу.

Для реальных обновлений нужны отдельно: доверенная модель открытых столов, интеграционные испытания на Android, проверка доступности GPT-модели, подпись релизов и безопасное развёртывание.

## Политика развития

1. Разработчик выпускает новый артефакт с новой версией, не перезаписывая старый.
2. Создаёт draft релиза и прогоняет единые тестовые изображения и истории (без оценки личной игры пользователя).
3. После проверки и ручного одобрения выпускается checkpoint с test report.
4. Переключение только после полного выхода и подтверждения отсутствия открытых столов.
5. Для восстановления выбирают любой проверенный checkpoint, в том числе значительно старше текущего.
6. Сведения о сыгранных раздачах и реальном балансе никогда не возвращаются в прошлое.

Тестовые чекпоинты имеют `scope=registry_lab`: **в реальном окружении нельзя считать их проверенными и использовать для денежных действий**.
