# AI Remote Control GPT v1.8 — Trace Lab & Phone Capture-to-Reply

**Статус:** лабораторное обновление модульного проекта v1.7. Нет APK, живого GPT API, проверенного таймера хода и функции автоматических денежных ставок.

## Что добавлено

1. `server/arc_telemetry/trace.py` — потокобезопасный ограниченный реестр временных трасс. Учитывает capture, encode, uplink, vision, model, downlink, verify по отдельности; хранит только длительности и идентификаторы сессий, не хранит изображения, персональные сведения или содержимое ставок. Гарантирует монотонность последовательностей кадров, отклоняет stale/duplicate/out-of-order/overlaid экраны, выбрасывает предыдущую незаконченную работу при поступлении нового кадра. **Не даёт разрешений на касания**.
2. `server/arc_telemetry/lab.py` — воспроизводимая симуляция задержек с тремя синтетическими профилями. В `BENCHMARK_v1.8.json` записаны **придуманные для проверки логики временные значения**, не производительность реального GPT, сети, Android или 1win.
3. `android/app/src/main/java/com/example/airemote/ClientTraceWindow.kt` — измерение *capture→reply* в единой монотонной временной области Android, с окном p95 и пометками `SUPERSEDED` и `STALE_RESPONSE`. Никакого разрешения выполнять действие.
4. `CaptureService.kt` — в тестовом режиме быстрой передачи добавлен сбор и вывод Android RTT и capture→reply p95 в строке состояния. Совместимо с существующим локальным режимом, на телефон не устанавливалось.
5. 11 новых Python-тестов, автономный Kotlin-тест `ClientTraceWindowTest.kt`, предыдущие тесты сохраняются.

## Важные ограничения

- **Не синхронизируйте время сервера и Android, вычисляя разницу между их абсолютными timestamp.** Для Android end-to-end измерения используется только `SystemClock.elapsedRealtime()`, а серверные стадии — отдельные длительности.
- Надпись таймера 30/60 с не равна времени до конца хода. `timer_verified=false` и `money_actions_enabled=false` всегда.
- Данные симуляции *не подтверждают*, что система сможет уложиться в 30-секундное ограничение на реальном телефоне. Для этого ещё нужны реальные измерения сети, MediaProjection, модели, проверки состояния и поведения Android.
- UI detector может ошибаться на ранее не встречавшихся состояниях. Предназначено для наблюдения и безопасного офлайн-тестирования, не для реальных ставок.
- В проекте **не реализованы** маскировка бота, обход антибот-проверок или автоматическая игра на деньги.

## Проверка

```bash
cd server
python -m unittest discover -s tests -q
```

Отдельные JVM-тесты без Android SDK:

```bash
cd android
kotlinc app/src/main/java/com/example/airemote/ClientTraceWindow.kt tests_fast/ClientTraceWindowTest.kt -include-runtime -d /tmp/clienttrace.jar
java -jar /tmp/clienttrace.jar
```

Для моделирования:

```bash
cd server
python -c 'from arc_telemetry.lab import replay_traces; print(replay_traces()["summary"])'
```
