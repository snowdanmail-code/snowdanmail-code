# AI Remote Control — техническое задание и результаты v0.5

## Цель

Проверить цикл GPT-driven управления Android: изображение экрана → классификация состояния покерного стола → команда → физический Android-жест по операторской калибровке → новый кадр. Пользователь запускает процесс и может прервать его. Поддерживается работа поверх стороннего Android-приложения; **факт работы в 1win пока не установлен**.

## Реализовано в исходниках

| Узел | Реализация | Проверка |
|---|---|---|
| Экран | MediaProjection foreground service, Android 10+ | Android не проверялся |
| Передача | JPEG Q55/Q75/Q88, 720/960/1280, newest-only | Предыдущие серверные тесты |
| API | Python stdlib loopback HTTP и токен | Автотесты |
| GPT | OpenAI Responses API, JSON-schema `poker_frame_decision` | Мок-тесты, живого ключа не было |
| Действия | `dispatchGesture`, package guard, action→calibrated XY | Исходники, без проверки на телефоне |
| Безопасность | тайм-аут, лимиты, свежий кадр, STOP, fail-closed | Python-тесты и статическая проверка |
| 1win | Подключение к клиенту, OCR-калибровка, прогон раздач | **Не выполнено** |

## Модель угроз и отказов

- GPT может не распознать знак валюты, сумму Call или то, чей ход. Требуется независимая OCR-проверка, данные должны подтверждаться перед любым финансовым нажатием.
- Изменение интерфейса может перенести калиброванную кнопку. Проверяется `packageName`, но не кнопка под точкой: это критическая незавершённая часть.
- Сумма разыгранных чипов из GPT — **не проверенный реальный расход**. При реальных деньгах требуется отдельная независимая защитная подсистема по балансу и границам ставок.
- Кадр может устареть за время вывода GPT. При несоответствии локальной последовательности кадра Android прекращает сессию.
- Принудительная остановка доступна из постоянного уведомления. Аккаунты и платёжные данные не должны попадать в поток изображений.
- Симуляция поведения человека для сокрытия бота и обход антибот-защиты не реализована и не входит в задачи.

## Реальные дальнейшие испытания

1. Собрать APK на Windows; провести тест захвата на Android 16, включая поворот и изменения интерфейса.
2. Настроить кнопку по учебному приложению и проверить правильность и точность кликов.
3. Проверить визуальный парсинг десятков независимых скриншотов реального интерфейса 1win, не делая денежных нажатий.
4. Ввести независимый анализ состояния стола (не только уверенность GPT), тесты на ошибок на таймере и интерфейсных переходах.
5. Проверить денежные предохранители и только потом обсуждать пригодность реальных ставок.

## Контрольный срез

Сервер: 97/97 тестов пройдено. Android: не компилировался в контейнере — нет Android SDK/Gradle. Включение API требует собственный ключ OpenAI, который не предоставлен.

## Машина состояний

`cash_lobby → buyin_dialog → table_waiting → table_playing ↔ action_controls ↔ raise_panel → showdown → table_waiting`.

Переходы не предполагают автоматическое нажатие: новый модуль пока распознаёт и проверяет экран. Ошибка распознавания, неожиданное окно или наложенный UI сбрасывают состояние в `unknown`.

## Границы достоверности

- Ручная разметка семи изображений успешно подготовлена. Это **не** означает, что GPT уже показал 100% точность на этих файлах — настоящего OpenAI API-ключа и живого теста не было.
- Текущая документация включает исходники Android; **APK не собран** — здесь отсутствует Android SDK.
- Лимит 5% используется как **консервативное инженерное правило отбора**, не как гарантия безопасности или доходности.
- Передавать по сети изображения счёта/платёжных данных нельзя без осознанного согласия. Для локальных тестов отдельно проверять оповещение MediaProjection и STOP.
