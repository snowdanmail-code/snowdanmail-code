# AI Remote Control GPT v2.11 — сохраняемая аварийная остановка

## Что действительно реализовано

Это исходники Android/сервера, **не готовый APK** и не проверенное автономное управление приложением 1win. Предполагаемый оператор — владелец телефона. ИИ-игрок проектируется для режима **бесплатных условных фишек**.

В v2.11:

1. `OperatorStopStore.kt` сохраняет аварийную остановку в Android `SharedPreferences` с синхронной записью (`commit`). Первое включение считается остановленным; разрешение новой сессии требует явной кнопки оператора.
2. `MainActivity` сохраняет STOP до отправки команды фоновой службе; проверяет сохранённое состояние и после возвращения из фона.
3. `CaptureService` проверяет сохранённый STOP при запуске захвата, потока и игрового режима; команда STOP из уведомления также сохраняет остановку.
4. `DemoAccessibilityService` проверяет тот же STOP перед пробными жестами; внешние игровые жесты остаются **жёстко отключены** во флаге сборки `EXTERNAL_GAME_ACTIONS_ENABLED=false`.
5. Предварительная проверка обнаруживает отсутствие сохранённой остановки, нарушение защитного флага и ошибки версии. Исправлены ложноположительные тесты конфигурации.
6. Сборка Windows теперь запускает `:app:testDebugUnitTest` **до** `:app:assembleDebug`, как и GitHub Actions/Linux-скрипт. Проверка настоящего APK требует `aapt`, `apksigner`, соответствия версии и SHA-256.

## Что проверено в этой рабочей среде

- 366 серверных unit-тестов — PASS.
- 44 теста лабораторного модуля авторизации на синтетических данных — PASS; реальной авторизации ChatGPT Plus **не было**.
- 18 тестов стратегии на искусственных ситуациях — PASS.
- 21 тест инструментов и конфигурации Android — PASS.
- Kotlin/JVM: 12 сценариев `PlayChipTurnGuard`, 9 проверок `OperatorControl`, 7 проверок сохранения STOP через подставной Android Context — PASS. Подставной Context проверяет логику, **не поведение на физическом устройстве**.
- Офлайн-HTTP smoke — PASS.
- `android_preflight.py --strict` — PASS; SDK недоступен, это **не** компиляция Android.

## Что ещё не подтверждено

- Компиляция и установка APK. В доступной среде отсутствуют Android SDK 35 и Gradle 8.9, а у GitHub-интеграции нет доступного репозитория для CI.
- Вход через ChatGPT Plus / `Sign in with ChatGPT`, получение действительного GPT-ответа по подписке.
- Практическая работа на Android с оригинальным интерфейсом 1win; никакой автоматической внешней ставки не выполнено.
- Допустимость автоматического управления по применимым условиям площадки. Бесплатные фишки не подтверждают это автоматически.

## Как получить проверяемый APK

### Вариант A: GitHub Actions

Загрузить каталог проекта (включая `.github/workflows/ci.yml`) в приватный репозиторий, которому предоставлен доступ GitHub Actions. Workflow `Android APK + offline checks` ставит Java 17, SDK 35, Gradle 8.9, запускает тесты и сборку, проверяет подпись и SHA-256. При успехе артефакт `ai-remote-control-v2.11-debug-apk` содержит `AI-Remote-Control-v2.11-PLAYER-LAB.apk`. **В этой сессии workflow не запускался.**

### Вариант B: Windows

Нужны Java JDK 17, Android SDK Platform 35 + Build Tools 35.0.0, Gradle 8.9 и Python 3. В PowerShell запустить `windows/01_BUILD_APK.ps1`. При подтверждённом результате архив содержит инструкцию `windows/03_CONNECT_PHONE.ps1`; она используется только после сборки. Никакого фиктивного APK скрипты не создают.

## Границы испытаний

Автоматический игровой цикл с условными фишками можно проверять в собственном тестовом клиенте. Исходники ориентированы на анализ экрана исходного Android-приложения 1win, однако до проверки правил внешнего сервиса реальные автоматические нажатия там выключены. Не использовать для денежных ставок и обхода ограничений площадки.
