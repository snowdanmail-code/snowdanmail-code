# AI Remote Control v0.5 — 1win UI recognition + поток GPT (экспериментальные исходники)

**Статус:** серверный прототип + исходники Android. **НЕ готовый APK; не проверено на Android и в 1win, не использовался реальный баланс.** Для реальной эксплуатации необходимы сборка Android, калибровка реального интерфейса, валидация точности распознавания и испытания с учебными фишками. При ошибочном распознавании GPT способен нажать неверную кнопку — никакого выигрыша не гарантируется.

## Новое в v0.5

- В Android добавлена кнопка **«2A. Распознать экран покера»**. Она отправляет JPEG на `/poker/screen` и показывает JSON-наблюдение и оценку столов. Это **только чтение**; нажатия/пополнение/бай-ин не выполняются.
- Новый `server/lobby_agent.py`: GPT через OpenAI API классифицирует **лобби, диалог бай-ина, ожидание, игру, доступный ход, рейз, вскрытие**. Отдельно извлекает строки столов, занятость, блайнды, лимиты входа, банковый баланс, карты, общие карты, банк, таймер и видимые кнопки. Неуверенные сведения возвращаются как `null`.
- `rank_tables`: предварительно отбирает **только Holdem NL**, с незаполненными местами и подтверждёнными блайндами и минимумом входа. По умолчанию минимум входа не должен превышать **5% явно известного баланса**. При недостаточной информации результата нет. Такой фильтр не обещает выигрыша и не является инструкцией поставить деньги.
- `buyin_preview`: вычисляет долю минимального бай-ина от отображённого баланса. При балансе **$4.27** и минимальном входе **$1.60** доля **37.47%**, рекомендация автоматического входа отключена.
- `screenshots_manifest.json`: ручная разметка 7 предоставленных скриншотов: состояния и приблизительные прямоугольники UI на холсте **709×1536**. **Исходные скриншоты и аватары в архив не включены**, чтобы не распространять личные данные. Координаты в разметке — не разрешение для касаний на реальном устройстве.
- `navigation_fsm.py`: проверка последовательности экранов, отказ при низкой уверенности/невозможном переходе. **Нет автоматической посадки/покупки бай-ина.**

## Что добавлено в v0.4

- `/poker/decide`: принимает один JPEG и метаданные сессии, отправляет изображение GPT (OpenAI Responses API, строгое JSON-описание ответа), возвращает одно из `fold`, `check`, `call`, `raise`, `wait`, указанную моделью стоимость действия и неопределённость.
- Управление через `AccessibilityService.dispatchGesture`: при явном запуске оператором программа может выполнить реальные касания **в выбранном оператором Android-приложении**. Это не ADB, не симуляция кнопок внутри AI Remote Control. Активное окно должно совпадать с заданным `packageName`.
- GPT **не получает право назначать произвольные координаты**. Координаты кнопок задаёт пользователь отдельно, как нормализованные центры в текущем окне. Например, структура `{"fold":[X,Y],"check":[X,Y],"call":[X,Y],"raise":[X,Y]}`. **X/Y нужно измерить на реальном телефоне, никаких рабочих значений по умолчанию нет.**
- Предохранители: ручное начало сеанса, видимое Android-уведомление и STOP, лимит 20 жестов/30 запросов на сессию, проверка активного приложения и свежести кадра, новая картинка после действия, подавление повторов за 8 сек, лимит суммы ставок в чипах на сервере. При ошибке агент прекращает сеанс. **Поскольку суммы получены из изображения, эти лимиты не гарантируют защиту денежных средств.**
- Публичное внешнее управление сервером не предусмотрено, не реализованы маскировка поведения, подмена устройства, антидетект или обход защит.

## Архитектура

```text
Android MediaProjection → JPEG в ОЗУ → POST /poker/decide
                                          |
                                  OpenAI Responses API
                                          |
                               {action, cost, confidence}
                                          |
Android: проверка ответа → проверка packageName →
проверка свежести кадра → сопоставление action с КАЛИБРОВКОЙ →
AccessibilityService.dispatchGesture → новая картинка / STOP при ошибке
```

**Это последовательность отдельных кадров, а не непрерывная видеомодель.** Отправка одного кадра, ожидание ответа GPT и проверка результата может занимать несколько секунд. Таймер на покерном столе может истечь раньше. Захват защищённого содержимого может возвращать чёрный экран.

## Сборка Android на компьютере

1. Откройте `android/` в Android Studio, установите Android SDK 35 и JDK 17, Gradle 8.9.
2. В исходниках отсутствует Gradle Wrapper JAR (`gradlew`, `gradle-wrapper.jar`), поэтому для первичной подготовки понадобится установленный Gradle или добавление Wrapper в Android Studio.
3. Соберите Debug APK, установите на Android 10+. В системных настройках включите предоставляемую приложением Accessibility-службу.
4. На каждый сеанс вручную разрешайте захват экрана через Android MediaProjection. На Android 14+ разрешение необходимо получать вновь при новом сеансе. Для сервера на том же телефоне используйте Termux.
5. В приложении задайте адрес API `http://127.0.0.1:8787` и `ARC_DEVICE_TOKEN`, а также точное Android-имя пакета игры и **проверенные** координаты кнопок. При другом размере экрана / повороте / расположении кнопок калибровка становится недействительной.
6. Нажмите «Запустить сессию», затем переключитесь в целевое приложение. Если server `.env` не разрешил действия, GPT будет только анализировать. Уведомление содержит STOP захвата.

## Как запустить сервер (локально, без аренды GPU)

```sh
cd server
export ARC_DEVICE_TOKEN='ДЛИННЫЙ_СЛУЧАЙНЫЙ_ТОКЕН'
export OPENAI_API_KEY='ВАШ_СЕКРЕТНЫЙ_КЛЮЧ'  # хранить только на сервере
export ARC_OPENAI_MODEL='gpt-5-mini'
python server.py
```

Нужен Python 3.10+ (встроенные библиотеки, дополнительных pip-зависимостей нет). Сервер привязан к `127.0.0.1:8787`. **Без `OPENAI_API_KEY` реального анализа GPT и внешних игровых действий нет.** Ключ никогда не вводится в APK. OpenAI API оплачивается отдельно от ChatGPT.

### Управление разрешениями на действия

**По умолчанию: любые внешние действия отключены.** Для экспериментов в среде с учебными фишками в окружении сервера есть явные настройки (без изменения исходников):

```sh
export ARC_ENABLE_POKER_ACTIONS='1'
export ARC_MAX_SINGLE_WAGER_CHIPS='1'
export ARC_MAX_SESSION_WAGER_CHIPS='5'
```

Значения означают условные чипы, **не деньги**. Пока `ARC_ENABLE_POKER_ACTIONS` не задан равным `1`, сервер возвращает `wait`. Для нового маршрута `/poker/screen` любые денежные действия заблокированы независимо от настроек. При нулевых лимитах доступны только бесплатные действия `check`/`fold` (если включены), а `call`/`raise` блокируются. Для `raise` требуется предварительно проверенная одношаговая кнопка с фиксированной ставкой; ввод произвольной суммы в поле ставки **ещё не реализован**.

## Нельзя считать готовым

- Нет подтверждённого `packageName` 1win и его реальной калибровки. Нет живого теста на Android.
- **Вход в 1win, выбор стола касанием, подтверждение бай-ина, ввод Raise и автоматические реальные денежные ставки в v0.5 не реализованы.** Маршрут анализа лишь выделяет состояния, чтобы позже проектировать переходы и защищённые касания.
- Нет независимой проверки карт и чисел: GPT может ошибаться даже при `confidence=0.99`.
- Реальный баланс/валюта, выигрыши и потери не проверяются: счётчик затрат на сервере — **оценка по сообщениям GPT**, не бухгалтерская защита.
- Нет защиты от изменений размера окна, всплывающих диалогов внутри целевой игры, обновления интерфейса и неправильной цены Raise.
- Не проверено, разрешает ли конкретный клиент стороннюю автоматизацию.
- Не гарантировано, что `MediaProjection` захватит защищённый игровой экран.

**Не использовать для денежных ставок до проверки всех этих условий.** Это экспериментальная инженерная версия, а не готовый автоматический игрок в 1win.

## Тесты

```sh
cd server
python -m unittest discover -s tests -q
```

Проведено **97 серверных тестов**, включая проверку JSON, отсутствия ключа, блокировки по умолчанию, резервирования бюджетов, отказа в повторах, авторизации и потоковой памяти. OpenAI-запросы в тестах мокируются. Настоящий OpenAI API и APK не тестировались.

Официальная документация: https://developer.android.com/media/grow/media-projection  ; https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#dispatchGesture(android.accessibilityservice.GestureDescription,%20android.accessibilityservice.AccessibilityService.GestureResultCallback,%20android.os.Handler) ; https://platform.openai.com/docs/api-reference/responses

## v0.6 — отдельный модуль разбора истории **только после полного выхода**

Подробности: [`POST_SESSION_REVIEW.md`](POST_SESSION_REVIEW.md).

Модуль: `server/post_session_reviewer.py` (изолированный, без Android-команд). Модуль **не запускается во время игры или после одной раздачи**. Для разрешения анализа требуется подтверждение завершения выхода за столом и отдельная проверка страницы «Мои столы» с нулём открытых столов. Сомнение, переподключение или возвращение к игре блокируют разбор.

Код анализатора и серверные тесты готовы; реальный Android-интеграционный триггер, взаимодействие с Replay и живой GPT-анализ пока не реализованы и не проверены.
